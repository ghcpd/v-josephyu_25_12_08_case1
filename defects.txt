# DEFECTS FOUND IN README.md

## Defect 1: Incorrect app.run() command-line arguments
**Location:** Section 3.3 "Start the App"
**Severity:** HIGH
**Description:** 
The README states to run: `python app.py --host=0.0.0.0 --port=8080`
However, Flask's development server does not accept these arguments when passed to app.py directly.

**Error Trace:**
The arguments are ignored - app.run() is called without parameters, so it defaults to 127.0.0.1:5000

**Reproduction:**
1. Create and activate virtual environment
2. Install dependencies: `pip install -r requirements.txt`
3. Run: `python app.py --host=0.0.0.0 --port=8080`
4. Observe: App runs on http://127.0.0.1:5000, NOT on 0.0.0.0:8080

**Fix:**
Either:
- Option A: Modify app.py to use `app.run(host='0.0.0.0', port=8080, debug=True)`
- Option B: Use Flask CLI: `flask run --host=0.0.0.0 --port=8080`
- Option C: Document the actual default behavior (127.0.0.1:5000)

**Correct Commands:**
```powershell
python app.py  # Runs on http://127.0.0.1:5000

# OR using Flask CLI:
flask run --host=0.0.0.0 --port=8080
```

## Defect 3: Inconsistent database configuration documentation
**Location:** Section 4.2 "Database"
**Severity:** MEDIUM
**Description:**
The README states:
- "Database file name: `database.sqlite3`"
- "Location: `data/` subdirectory under the project root"
- "The legacy `app.db` name is no longer recommended"

However, the actual code in app.py shows:
```python
app.config['DATABASE'] = 'app.db'  # SQLite file at root of workspace
```

The actual implementation uses 'app.db' in the root, not 'data/database.sqlite3'.

**Error Trace:**
Database is created as app.db in the root directory when init_db() is called.

**Reproduction:**
1. Run the Flask app
2. Observe: app.db is created in the root, not data/database.sqlite3

**Fix:**
Update documentation to reflect actual implementation:
```python
app.config['DATABASE'] = 'app.db'  # SQLite file at root of workspace
```

**Corrected Documentation:**
- Database file name: `app.db`
- Location: Root of the project directory
- Configuration: `app.config['DATABASE'] = 'app.db'`

## Defect 7: Virtual environment activation path escaping issue
**Location:** Section 3.1 "Create and Activate Virtual Environment"
**Severity:** LOW
**Description:**
The README shows double backslashes in the activation command:
```powershell
 .\\.venv\\Scripts\\Activate.ps1
```

While this technically works due to PowerShell's parsing, it's non-standard. The correct syntax is:
```powershell
.\.venv\Scripts\Activate.ps1
```

**Note:** This is minor but suggests the documentation may have been copy-pasted with escaping issues.
