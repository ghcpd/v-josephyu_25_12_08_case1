Defects found while verifying README vs implementation

1) README: Installation block contains invalid fence/typo
- Location: Section 3.2 (Install Dependencies)
- Issue: Closing fence had stray characters ("``` +") which breaks automatic rendering
- Reproduction: View README.md in a markdown renderer or attempt to copy code block; you'll see malformed fence
- Fix: Remove stray '+' and ensure standard fenced code block

2) README: Commands claim `python app.py --host=0.0.0.0 --port=8080` will bind to that address/port
- Location: Section 3.3 (Start the App)
- Issue: Original implementation did not handle CLI flags (app.run was called with defaults), so flags were ignored.
- Reproduction steps:
  - Run: python app.py --host=0.0.0.0 --port=8080
  - Expect: app binds to port 8080 on 0.0.0.0
  - Observed (before fix): app bound to default 127.0.0.1:5000
- Action taken: app.py updated to parse --host/--port and pass to app.run

3) README: Database path mismatch
- Location: Section 4.2 (Database)
- Issue: README states DB is `data/database.sqlite3` but code initially used `app.db` at project root.
- Reproduction steps:
  - Inspect app.py: app.config['DATABASE'] was set to 'app.db'
  - Running the app produced `app.db` in project root
- Action taken: app.py modified to set DATABASE to 'data/database.sqlite3' and models.get_connection now ensures the parent directory exists

4) README: Sessions & Redis claim
- Location: Section 4.3 (Sessions & Login)
- Issue: README claimed sessions were stored in Redis and that `SESSIONLESS_MODE=true` disables sessions. There was no Redis integration in code, and SESSIONLESS_MODE was not implemented.
- Reproduction: Code search for 'Redis' or 'SESSIONLESS_MODE' returned no usage. Starting app shows default Flask session behavior.
- Fix: Documentation updated to remove Redis claim and to describe actual session behavior (classic Flask sessions + Flask-Login), unless Redis is intentionally implemented.

5) README: Registration field expectations don't match implementation
- Location: Section 6.1 (Registration)
- Issue A: README said `email` is optional; implementation requires email (RegisterForm.email is DataRequired).
  - Reproduction steps:
    - GET /register to get CSRF token
    - POST /register with username and password but no email (include CSRF token): registration fails and returns form with validation error 'This field is required'.
- Issue B: README said password minimum length is 3; implementation enforces min length 6.
  - Reproduction steps:
    - GET /register to get CSRF token
    - POST /register with password length 3 (include CSRF token): form shows error 'Field must be between 6 and 128 characters long.'
- Evidence: See captured HTML from POST to /register showing CSRF token and validation messages (excerpt):

  <input id="csrf_token" name="csrf_token" type="hidden" value="...">
  <div class="text-danger small mt-1">Field must be between 6 and 128 characters long.</div>

- Fix: Updated documentation to reflect actual behavior (email required, password min 6). Alternatively, if the intended behavior is to accept email-less signups and min 3 passwords, adjust the form validators accordingly.

6) CSRF not documented for programmatic posts
- Location: Implicit in forms sections
- Issue: The README did not mention that forms use CSRF protection. Programmatic POSTs without CSRF tokens silently fail validation.
- Reproduction steps:
  - POST /register without csrf_token -> registration does not create a user and returns the form
  - Observed that HTML form includes a hidden csrf_token and server-side validation expects it
- Fix: Corrected docs to explicitly mention CSRF and show how to fetch token for programmatic tests

7) Tests: initial pytest collection error (Module import issue)
- Location: N/A (test setup)
- Issue: Running pytest from project root without adjusting PYTHONPATH resulted in `ModuleNotFoundError: No module named 'app'` during test collection (tests/test_app.py attempted direct import).
- Reproduction:
  - Run: pytest
  - Stack trace excerpt:
    ModuleNotFoundError: No module named 'app'
- Fix: Test file updated to insert project root into sys.path (tests/test_app.py now sets sys.path to include repository root). Alternatively, a package __init__ file or proper PYTHONPATH setup could be used.
